# Working on Zgame

- **The in-game Guide (`client/src/pages/Guide.tsx` for the page, the topics in `client/src/guide/`: start, play, world, community) is a player manual**, strictly about how to play: features, rules, numbers and nuances. It is never an update log: no "new", "now", "changed", "was", dates or version talk. When a change alters something players or admins see or do (a feature, a rename, a rule or number, a setting), **edit the matching topic in place** so the Guide always describes the game as it is, or add a topic for a brand-new system. Do this in the same commit as the change. `test/guide.test.ts` enforces the tone and that every screen and key system is covered; extend its lists when you add one.
- **The tutorial is part of this too**: the welcome tour (`client/src/Tour.tsx`, one step per main page) and the guided objectives (`server/progress.ts`) must match the game as it is. When a change adds, renames or removes a page or a first-hours mechanic, update the tour step or objective hint in the same commit. `test/tour.test.ts` checks the tour only points at real pages and covers the main ones.
- **The hands-on tutorial too** (`client/src/tutorialSteps.ts`, shown by `Tutorial.tsx`): it points at real elements marked `data-tour="..."` and moves on when the game state shows the step was done. When a change moves, renames or removes a button, page or mechanic the tutorial uses (Buildings, the build buttons, the queue, item links, Back, Research, Tech tree, Galaxy, Overview), fix the step and its `data-tour` mark in the same commit; when a change adds something a newcomer must learn in the first hour (a new first-hours mechanic, a main page, a new way to act), add a step. `test/tutorial.test.ts` checks every target exists and the move-on rules; the browser test plays the first steps. Say in the final reply that the Guide, the tour/tutorial and What's new were checked or updated.
- **Names and coordinates are always links.** Any screen that shows a coordinate, a commander name or a planet name must make it a working link: use `CoordLink`, `PlayerLink` and `PlanetLink` from `client/src/ui.tsx` for structured data and `Linkify` for free text (it finds `[g:s:p]`, commander names and your own planet names). Messages and reports must carry the owner ids their links need. Native `<select>` options are the only exception.
- **Release notes live elsewhere**: `client/src/changelog.ts`, shown on the *What's new* page (banner + Settings link). Add an item to the newest entry for each player-visible change (start a new entry with a new `id` for a batch, so the banner shows again).
- Internal-only work (refactors, tests, deployment) needs neither; deployment and settings go in `README.md` / `docs/DEPLOY.md`. Server-operation details (environment variables, backups) do not belong in the Guide.
- **Every feature gets:** tests, UI, a README note, a check in the real browser on a private port (never the default save or port 3000), then a commit.
- Players see **Vespene Gas**; the internal key is still `deuterium`. Use `resName()` from `shared/data.ts` when printing a resource key.
- `npm run balance:new` after changing crawler, class, orbit, merchant, shop or expedition constants.
- `npm run balance:invasion` after changing invasion strength, wave shares or alien kinds.
